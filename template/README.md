# <purpose>-knowledge — 知識の器

<目的> について、エージェントが判断の瞬間に必要とする知識を置く。
知識は「依頼の字義を超えて的と解を見つける」ための材料である。ここに無いものは世界（コード・データ・本人）を見て埋め、埋めたらここに書く。

## 構成

- `INDEX.md` — 索引。1トピック1行。セッション冒頭に読む唯一のファイル。40行を超えたら足すのではなく削る
- `topics/` — 事実の器。1トピック1ファイル、丸ごと読める大きさ（目安8,000字以内）。的が決まったら関係する1〜3枚を読む
- `moments/` — 瞬間の器。「数値を書く前に」「PRを出す前に」など、作業の瞬間ごとに1ファイル。その瞬間に丸ごと読む。引かせるのではなく届ける
- `hypotheses.md` — 経験の器。タスクごとの反証条件を1行で残し、次のセッション冒頭で読む。判定は人間

## 書き方

各事実は1行の箇条書きで、頭に信用ラベルと確認日を付ける。

- `[確認済み 2026-08-27]` — コード・データ・本人のいずれかで確認した
- `[要約 2026-08-27]` — 文書・Slack・Notion から要約した。コード・データ・本人で確認するまで確認済みにはならない
- `[仮説 2026-08-27]` — 根拠はあるが検証していない
- `[未確認]` — 分からないと分かっていること。誰に・どこで確認できるかを添える

出典はファイル末尾の脚注 `[^n]` に置き、本文には書かない。成果物（画面・文書・PR）に出典ラベルや内部参照記号を持ち出さない。
決定は `## 決定` 節に日付・内容・理由で置く。トピックの外に決定の器を作らない。
統治語彙（台帳・verdict・較正・evaluator・宣言・T007 等のタスク番号）を書かない。ここを読むのはタスクの中の自分である。

## いつ書くか

1. 世界を見て未知を埋めた直後（コードを読んで分かった、データを引いて分かった）
2. 本人に訂正された直後。これが最も価値の高い1行である
3. 成果物を出した直後に、反証条件を `hypotheses.md` へ1行

書くときは既存ファイルに統合する。同じ事実を2箇所に置かない。矛盾したら古い方を消し、消した事実は脚注に「2026-09-02 撤回」と残す。

## 書かないもの

- 各リポジトリの CLAUDE.md / AGENTS.md / README に既に書いてあること（そこを指す1行で足りる）
- git log・ファイル構成など、コマンド1本で再取得できる観測
- タスクの進行状態（それはタスクの中に置く）
