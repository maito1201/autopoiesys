# 判定サブエージェントのコストを、独立性を落とさずに下げる

## 実測（この計画の根拠）

T016（1タスク）の内訳:

| 項目 | 実測トークン |
|---|---|
| 独立判定・監査サブエージェント6本 | 561,501（1本 45k〜128k、ツール呼び出し8〜58回） |
| OSが組んだ文脈（briefing 6本・想起・Reasoning Context） | 53,169 |
| Query | 約40,000 |

支配的なのはOSの文脈構築ではなく、**判定サブエージェントの自力探索**である。
briefingは1本3.7kにすぎない。削る対象を間違えると効かない。

## 何を変えるか（ユーザーが選んだ3つ）

1. **同一状態の再判定を機械的に止める。** 前回のverdict以降に成果物が1件も変わっていない
   llm_judgeは、briefingを作らず「同じ状態を再判定する必要はない」と返す。
   T016では指摘1件ごとに判定を回して5ラウンドになった
2. **成果物を差分で提示する。** briefingのArtifact節をパスごとに最新1件へ畳み、
   前回の判定以降に変わったものに印を付ける。T016のbriefingには同じパスが何度も並び、
   判定者は20件超を毎回読み直していた
3. **evaluatorのtierからモデル階層を導く。** llm_judgeの保留出力とbriefingに、
   evaluator定義の `tier` と `config.yaml` の routing 表から引いたモデルを出す。
   定型判定と要件充足の判定を同じモデルで回さない（未着手だったG3の実配線）

**判定者の探索範囲そのものには上限を課さない。** 自分で確かめることが独立評価の値打ちであり、
そこを削ると安くなった代わりに検出力が落ちる（ユーザーはこの選択肢を採らなかった）。

## 受け入れ条件（実装の結果を見る前に固定する）

1. 成果物が変わっていない状態で `evaluate` を2回実行したら、2回目はllm_judgeのbriefingを
   再生成せず、その理由を返す。成果物を1件でも登録したら再び生成される
2. 同じパスを複数回登録したタスクのbriefingで、Artifact行がパスごとに1行になり、
   前回の判定以降に変わったものに印が付く
3. llm_judgeの保留出力に、evaluator定義の tier と routing 表から引いたモデルが出る
4. `node --test` 全件・`regression` 全件・docs-drift・skill-commands が通る
5. 実測: 同一タスクのbriefingを新旧で比べ、トークンが減っていること（増えたら失敗と書く）

## 前提の棚卸し

| 前提 | 出所 | 対処 |
|---|---|---|
| トークンコスト対策の優先度が上がった | ユーザー指定 | 固定制約 |
| 削る対象は判定ラウンド数・成果物の提示・モデル階層の3つ | ユーザー指定（選択肢から選んだ） | 固定制約。探索範囲の制限は採らない |
| 支配的コストは判定サブエージェント | 測定（サブエージェント6本の実測値とcontext_logの突き合わせ） | 数値をこの文書に転記した |
| briefingを小さくすること自体は効果が小さい | 測定（briefing 3.7k vs 判定者 45k〜128k） | 2の狙いはbriefingの大きさではなく、判定者が読むファイルの件数である |

## 実装後の実測（受け入れ条件5）

briefingの内訳を測ったら、変更2の狙いは外れていた。T016のbriefing（6回evaluate後）の
66%（3,951トークン）は「OSが記録した検証実績」節で、**evaluateのたびに全履歴分だけ
膨れ続ける**。Artifactの畳み込みが効いたのは166トークンだった。

そこで4つ目の変更を追加した: **検証実績もevaluatorごとに最新1件（evidence抜粋≤3行）へ畳み、
過去はverdictの推移1行に残す**（判定が往復した事実は判定材料なので落とさない。
判定中のevaluator自身は従来どおり除く）。

同一タスク（T016）のbriefingを新旧で比較した結果:

| briefing | 旧（全履歴） | 新（畳み込み後） | 削減 |
|---|---|---|---|
| requirement_satisfied | 5,992 | 2,790 | -53% |
| objective_alignment | 6,884 | 2,838 | -59% |

（context_log.jsonl 2026-08-29T16:51:59Z / 16:54:25Z の機械実測。トークンは推定値）

旧方式は上限が無く、evaluateを重ねるほど差は開く（T016は2,003→6,884まで単調増加していた）。

## 変更履歴

- 初版: T017の実装前に事前固定した。
- 実装後: briefing内訳の実測（検証実績66%）を受けて変更4（検証実績の畳み込み）を追加し、
  受け入れ条件5の結果を転記した。受け入れ条件1〜3は変更していない。
