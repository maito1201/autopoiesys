# 台帳が自分の状態を誤って写す2つの穴を塞ぐ（F013・F015）

## 受け入れ条件（実装の結果を見る前に固定する）

1. 誤登録したタスクを取り下げられる（F013）。`task withdraw <id> --reason "<理由>"` が
   `status: withdrawn` にする。**成果物もverdictも無いタスクに限る** — 何かが行われた
   タスクを消せる経路にしない（失敗を隠す道具になる）
2. 取り下げたタスクは、未評価の警告にも成長の系列（試行）にも数えられない。
   理由の記録は必須で、消さずに残る
3. 宣言した知識源が取り込まれているかを検査する（F015）。`goal.yaml` の
   `sources[].memory_dir` / `rule_docs` に実在するファイルのうち、World Modelに
   対応するノードが無いものを検出する。実測: memoryは9ファイル中4件しか入っておらず、
   goal監査は記録された意図の56%を見ずに回っていた
4. 3の検出器は「読めなかった」を「無い」と混同しない（読めない知識源は違反として出す）
5. 両方に検出力fixture付きのgolden taskを追加する（片方向だけ通る実装では赤くなる）
6. `node --test` 全件・`regression` 全件・docs-drift・skill-commands が通る

## 前提の棚卸し

| 前提 | 出所 | 対処 |
|---|---|---|
| 残タスクを片付ける | ユーザー指定 | 固定制約 |
| 取り下げは「何もしていないタスク」に限る | 自分で決めた | load-bearing。緩めると失敗の隠蔽経路になる。受け入れ条件1で縛る |
| 憲章の基準の質（分母を持たない存在述語）は今回触らない | ユーザー判断（憲章の変更はc-004のみ採用） | 提案として残し、適用しない |
| 知識源の取り込み漏れは検出器で防げる | 自分で決めた | 実測1件（memory 9→4）。n=1であることを報告に書く |
