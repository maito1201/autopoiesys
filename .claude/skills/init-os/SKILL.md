# init-os — 思考回路を作る

作るのは目的ごとのディレクトリ1つ（`template/` の形）と、CLAUDE.md の1行。回路はスキルに依存しない。
背骨は `.claude/skills/anti-bureaucracy/SKILL.md`。この手順自身がまずそれに従う。

## 1. アウトカムを確定する（まだ作らない）

最初の問いは白紙で: 「何ができるようになりたいですか」。ワークスペースの中身から目的を推測しない。
anti-bureaucracy の 1〜4 を書いて見せる。アウトカムは本人や読者の何がどう変わるかであり、「回路ができる」は要求の言い換えなので不可。
聞くのは人間にしか埋められないものだけ:
- 成果物を読む相手は誰か
- 触ってよい情報源（リポジトリ・実行ログ・Web・Notion・Slack）と、触ってはいけないもの
- 回路の置き場所と、CLAUDE.md のどれ（`~/.claude/CLAUDE.md` か対象リポジトリ）に配線するか
過去に何で差し戻されたかは聞かない。実行ログで埋まる。
既に器（INDEX.md・topics/）があるなら取り込む対象であり、作り直さない。

## 2. 広く集める

アウトカムが認められたら、許された情報源をすべて当たる。何を集めるかはアウトカムが決める。
1. 実行ログ: `scripts/corrections.sh ~/.claude/projects/<対象ディレクトリ>...` で本人の短い発話を出す。訂正・差し戻し・不満を拾い、同じ型を束ねる。束の件数と期間が瞬間の重みになる
2. リポジトリ: CLAUDE.md / README / docs / コード。CLAUDE.md にある事は写さず、指す1行にする
3. Web・Notion・Slack: 許可された範囲。要約由来は `[要約 日付]` のままにし、確認済みにしない
生の顧客名・連絡先・認証情報・秘密鍵を回路へ写さない。ログから写すのは蒸留した瞬間だけで、発話原文は残さず脚注に件数と日付を置く。

## 3. 整理する

- `topics/`: 1ファイル1トピック。ファイル名はそれが答える問い。事実は1行・信用ラベル・確認日。8,000字を超えたら分ける
- `moments/`: 訂正の束から「〜する前に／〜した後に」の形で作る。2件以上の訂正がある束だけを瞬間にし、1件は topics に置く。30行以内
- `INDEX.md`: トピック1行ずつ、その問い。40行以内
- `CIRCUIT.md`: template を写し、瞬間0「この目的で繰り返し出た未知」、瞬間2の目的固有の瞬間、瞬間3の読み手と最多の差し戻しを埋める。60行以内
- `hypotheses.md`: template の2行を日付を入れて書く。集め方・回路の形に固有の反証があれば足す

## 4. 配線する

- 回路を置き場所に書く。既存の器があるなら CIRCUIT.md を足し、README.md を template のものに差し替える
- CLAUDE.md に1行: `思考回路: <path> — 依頼を受けたら CIRCUIT.md を読み、瞬間ごとに従う。分かったこと・訂正は書き戻す`
- run-task / run-feedback を `~/.claude/skills/` へ symlink する（本人の承認後）
- `scripts/check.sh <path>` が OK を返すこと

## 禁止

- ワークスペースの中身から目的を推測すること
- アウトカムが認められる前に情報源を読み始めること
- 索引・分類・評価器・台帳など、読む瞬間の無い構造を足すこと。回路にあるのは「いつ・何を読む・何を疑う」だけ
- 統治語彙（台帳・verdict・較正・evaluator・宣言・タスク番号）を回路に書くこと
