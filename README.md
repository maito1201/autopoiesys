# autopoiesys — 知識の器の作り方

LLMエージェントに高度な仕事を任せられない原因は、知性の不足ではなく、判断の瞬間に知識が届かないことにある。
autopoiesys は「知識を、読む人がいつ必要になるかで分類し配置する」ための最小の規約と道具である。
検索エンジンも、評価器も、台帳もない。分類と配置が正しければ、知性の発揮は Claude の基本機能で足りる。

## 何があるか

- `template/` — 目的ごとの知識の器（knowledge home）の初期形。README（規約）・INDEX・hypotheses・topics/・moments/
- `skills/knowledge/SKILL.md` — 器の使い方と書き戻し方。`/knowledge` で呼ぶ
- `scripts/check.sh` — 器が官僚化していないかを wc と grep で見る

## 使い方

1. 目的ごとに器を1つ作る: `cp -r template ~/project/<purpose>-knowledge`
2. 各リポジトリの CLAUDE.md に1行足す: `知識の器: /path/to/<purpose>-knowledge — セッション冒頭に INDEX.md を読む`
3. 仕事の前に的を確定する（anti-bureaucracy）。的が決まったら INDEX から関係するトピックを1〜3枚読む
4. 作業の瞬間に moments/ の該当ファイルを丸ごと読む
5. 世界を見て未知を埋めた直後・本人に訂正された直後に、既存ファイルへ統合して書く。成果物を出したら hypotheses.md に反証を1行

## 設計の根拠

前身（2026-08、約1万行の Intelligence OS）の実測から:

- 知識850件のうち取り出しに使われたラベルは topic と信用度の2つだけ。type・confidence・id は一度も使われなかった
- 1回の取得で中央値1.6〜2.0万トークンを流し、12タスクで547万トークン。絞り込みは10%の呼び出しでしか使われなかった。引く側は何が要るか知らない
- 教訓8件はすべて「いつ」が本文にあるのにラベルが「いつ」を持たず、必要な瞬間に届かなかった
- 850件中タスクから生まれたのは6件。器は仕事から育っていなかった
- 出典ラベル（章番号・ID）が成果物に漏れ、読者から0点を受けた

これらの反証条件は各器の hypotheses.md にある。外れたら次の手は決まっている: 教訓が再発したら hook で機械的に届ける、事実を引けなければ検索を足す。
