# <purpose> — 思考回路

依頼を受けたらこのファイルを読む。仕事は瞬間の列であり、瞬間ごとに「読む物・疑う点」を置く。
これは知識の索引ではなく、いつ何を読むかの回路。60行を超えたら足さずに削る。

## 0. 依頼を受けた瞬間 — アウトカムを確定する

作り始める前に書いて見せる。アウトカム（誰の何がどう変わるか。要求文の言い換えは不可）、未知（まだ知らないこと。「ない」は主張）、埋め方（コード・データ・現場で埋まるものは自分で埋め、人間にしか埋められないものだけ聞く）。
アウトカムが認められるまでアウトプットを書かない。気づいた隙間を「仮定」と書いて進むのは官僚主義。
この目的で繰り返し出た未知:
- <init-os が訂正ログから埋める。例: Issue の確認事項は確定仕様ではなく、Figma の該当フレームと突き合わせる>

## 1. アウトカムが決まった瞬間 — 読む

INDEX.md から関係するトピックを1〜3枚、丸ごと読む。hypotheses.md の未観測行に同じ型の判断があれば読む。
5枚以上読みたくなったら、アウトカムが広すぎる。

## 2. 作る瞬間

字義との差分を書く。頼まれた物と作る物が違うならなぜか、同じならなぜ字義が最善か。「言われたから」は不可。
形式との差分も書く。選んだ形式（データ構造・モデル・抽象・仕事の単位）でアウトカムを運べるか、言葉でなら言えるのにその形式では書けないものは何か。空でないなら報告に書く。黙って落とすのが高難度での官僚主義の主形。
内容が3行を超える瞬間は moments/ に置き、ここから指す。その瞬間に丸ごと読む。
- <例: 数値を書く前に → moments/before-writing-numbers.md>
- <例: PR を出す前に → moments/before-opening-pr.md>

## 3. 報告する瞬間

読む相手は <誰>。この目的で最も多かった差し戻しは <何>。
反証を hypotheses.md に1行: この判断が外れていたら、何がいつ観測されるか。

## 4. 分かった瞬間・訂正された瞬間 — 書き戻す

コード・データ・本人を見て分かった直後に topics/ の既存ファイルへ統合する。本人の訂正は最も価値の高い1行。
「いつ」がある教訓は moments/ へ。同じ訂正が2回目なら瞬間として回路に足す。1回目は topics に置く。
規約は README.md。`scripts/check.sh <この回路>` で官僚化を見る。
