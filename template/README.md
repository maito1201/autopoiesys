# <purpose> — 思考回路

<目的> について、エージェントが判断の瞬間に必要とする知識を、必要になる瞬間ごとに配置する。
知識は「依頼の字義を超えてアウトカムとアウトプットを見つける」ための材料である。ここに無いものはコード・データ・本人を見て埋め、埋めたらここに書く。

## 構成

- `CIRCUIT.md` — 回路。依頼を受けてから書き戻すまでの瞬間を順に並べ、瞬間ごとに読む物と疑う点を置く。依頼を受けたら読む唯一のファイル。60行以内
- `INDEX.md` — 索引。1トピック1行、その問い。アウトカムが決まったら読む。40行以内
- `topics/` — 事実。1トピック1ファイル、丸ごと読める大きさ（8,000字以内）。関係する1〜3枚を読む
- `moments/` — 瞬間。「数値を書く前に」「PRを出す前に」など、CIRCUIT.md が指す先。1ファイル30行以内。引かせるのではなく届ける
- `hypotheses.md` — 反証の記録。成果物ごとに1行、次のセッション冒頭で未観測行を読む。判定は人間

## 書き方

各事実は1行の箇条書きで、頭に信用ラベルと確認日を付ける。

- `[確認済み 2026-08-27]` — コード・データ・本人のいずれかで確認した
- `[要約 2026-08-27]` — 文書・Slack・Notion・Web から要約した。コード・データ・本人で確認するまで確認済みにはならない
- `[仮説 2026-08-27]` — 根拠はあるが検証していない
- `[未確認]` — 分からないと分かっていること。誰に・どこで確認できるかを添える

出典はファイル末尾の脚注 `[^n]` に置き、本文には書かない。成果物（画面・文書・PR）に出典ラベルや内部参照記号を持ち出さない。
決定は `## 決定` 節に日付・内容・理由で置く。トピックの外に決定の器を作らない。
統治語彙（台帳・verdict・較正・evaluator・宣言・T007 等のタスク番号）を書かない。ここを読むのはタスクの中の自分である。
本人の発話原文・顧客名・連絡先・認証情報を写さない。訂正は蒸留した1行にし、脚注に件数と日付だけ残す。

## いつ書くか

1. コード・データ・本人を見て未知を埋めた直後
2. 本人に訂正された直後。これが最も価値の高い1行である
3. 成果物を出した直後に、反証条件を `hypotheses.md` へ1行

書くときは既存ファイルに統合する。同じ事実を2箇所に置かない。矛盾したら古い方を消し、消した事実は脚注に「YYYY-MM-DD 撤回」と残す。
回路そのもの（瞬間の順序・文言・指す先）を直すのは `/run-feedback`。

## 書かないもの

- 各リポジトリの CLAUDE.md / AGENTS.md / README に既に書いてあること（そこを指す1行で足りる）
- git log・ファイル構成など、コマンド1本で再取得できる観測
- タスクの進行状態（それはタスクの中に置く）
