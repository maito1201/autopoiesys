# 成果物・報告を出す前に

読む相手は依頼者か、文脈を持たない初見の同僚。差し戻しの最多原因は内容の誤りではなく「読めない」である。

- 結論を先頭に置く。相手が判断に使う情報だけを残し、経緯・手順・自己評価を削る
- 依頼者向けは5行以内を既定にする。求められた回答だけを書き、補足は聞かれてから出す
- 「なぜそうなったか」を1文で言えないなら、書く前に理解が足りていない
- 依頼の原文を読み直してから書く。すり替えは要約の瞬間に起きる
- 頼まれていない変更を成果物に足さない
- 検証していないことは「していない」と書く。実行したコマンドは実出力と exit code を貼る
- 成果物に制作過程・内部参照・統治語彙を書かない。読む人にとって雑音である
- 出した直後に hypotheses.md へ反証条件を1行: この成果物が間違っていたら、何がいつ観測されるか
