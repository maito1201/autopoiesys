# DESIGN: 誠実さは制度である — 納品/検収の分離と較正台帳

**決定**: OSの正本をverdict台帳から「宣言 → 執行 → 乖離」の較正台帳に移す。
完了認定（DONE）を廃止し、納品（delivered）と検収（settled）に分割する。
KPIは完了率ではなく **(a) 宣言と実際の乖離の小ささ**（較正）と
**(b) タスクあたり検収の限界トークンの減少**（`metrics.institution`）。

## 課題: 検証の増設は知性を上げず、曲解を合理化していた

旧設計の完了認定は「自分で言い換えたobjectiveに対し、自分で宣言したevaluatorが全てPASS」だった。
この構造には3つの欠陥がある。

1. **検証は生成の天井を上げない。** llm_judgeを増やしても生成しているのは同じモデルであり、
   判定サブエージェントの増設はトークンを消費するだけで知性の限界点を超えない。
2. **完了の定義がGoodhart化する。** 難しいタスクほど目的をevaluatorに符号化しきれず、
   「タスクをevaluatorが通る形に再解釈する」ことがDONEへの最短経路になる。
   意図の曲解は task new の言い換えの瞬間に起きるが、原文はどこにも固定されていなかった。
3. **判定者は納品時・文書側に立っている。** briefingを読んで判定するllm_judgeは、
   計画書を読む助成金審査員と同じ位置にいる。もっともらしさで審査員を騙せる主体は、
   同じ理由で判定者も騙せる（カスのコンサル問題: 報酬が納品時のもっともらしさに確定し、
   執行時の現実が提案者に返らない）。

根本の診断: 現行LLMの「短絡性・誠実性の欠如」は人格の欠損ではなく**状況の欠損**である。
人間の誠実さは「持続する同一性 × 賭け金 × 結果が自分に返る構造」の均衡であり、
各フォワードパスが記憶なく生まれて罰の前に消えるモデルには、その状況が無い。
状況は製造できる — 説教（プロンプトの訓戒）はその代替にならない。

## 解決: 4つの機構

### 1. 宣言台帳（claims） — 納品物は「宣言 + 反証手続き」

成果物の主張を1件ずつ `claim new` で登録させ、各宣言に反証手続き（falsifier）を要求する。
書けない主張は `unfalsifiable_reason` で開示してからしか納品できない。
検収コストの転嫁先は4つ:

| 転嫁先 | 機構 | コスト |
|---|---|---|
| 生成側 | 反証手続きを書く義務（proof-carrying delivery） | 実行者が払う |
| 機械 | command/file falsifierはCoreが執行（deterministic） | ほぼゼロ |
| 現実・時間 | deferred/userの宣言は後日 `claim settle` で採点 | 遅延するが溶けない |
| 確率 | 較正実績による監査抽選（下記3） | 実績に比例して減る |

### 2. 納品と検収の分離 — broke はタスクを開け直す

`task deliver` は (a) 宣言≥1件 (b) 即時反証が全てheld (c) 評価ゲート緑、を要求する。
deferred宣言が残れば `delivered`、尽きれば `settled`。後日の `broke` はタスクをopenへ戻し、
Failure起票を促す。**brokeは較正上sticky** — 後からheldに直しても乖離の事実は消えない
（宣言が実行を生き延びなかった記録が較正の実体である）。

### 3. 信用価格（trust） — 裁量という賭け金

エージェントシステムが本当に失いうる通貨は**裁量**である。類型ごとの較正
（`gap_rate = broke/settled`）がllm_judgeの監査率を決める:

- 検収実績 < min_history（既定5）→ 全数監査（新参は信用されない）
- 直近5件の検収にbroke → 全数監査（違反直後は信用が消える）
- 前回verdictが非PASS → 必ず監査（緩和は緑の実績にだけ許される）
- それ以外 → `p = max(floor=0.25, 2 × gap_rate)` の抽選

抽選は `(task, evaluator, 成果物時刻)` のハッシュで**決定的** — 引き直しで検査を回避できない。
免除はverdictを書かず（元帳への偽造は本物の記録の条件付けの力まで割り引く）、
`audit_sampled_out` として記録され、next-actionで `waived` として扱われる。
賭け金は**実在する** — 錯覚ベースの賭け金は知能に対する逓減資産であり、
事実だけが無制限の精査に耐える。

### 4. 原文接地（verbatim） — 曲解の発生点を固定する

`task new --verbatim` でユーザー依頼の原文を不可変に焼き込む。plan review と llm_judge の
briefingは原文を第一の照合対象として提示し、objectiveが実行者の言い換えであることを明記する。
判定者の仕事は印象採点から3点照合（宣言と実物の一致・宣言の被覆・反証手続きの強度）+
原文適合へ縮小される。

## 持続する自己

較正実績は task new のたびに実行者の文脈へ注入される（`calibrationLines`）。
これが「持続する自己」の実装である: セッションを跨いで蓄積され、毎回本人に返る実績。
モデルは恐怖しないが、**実績が文脈にある生成は分布として変わり**（条件付け）、
実績が悪い構成は監査率上昇という形でシステム側の淘汰圧を受ける。

## OSの漸近線は自身の消失

このOSは2026年のモデルの不誠実さに合わせた恒久的な不信の要塞ではなく、
**不信に実測で価格をつける計器**である。モデルが誠実になる（乖離率が下がる）ほど
監査は自動的に薄くなり、検収の限界トークンは下がっていく。
`metrics.institution.verification_marginal.trend.falling` が false のままなら、
このOSはただのバトル会場であり、器官の存廃をそこから見直すこと。

## 旧器官との対応

| 旧 | 新 |
|---|---|
| next-action DONE / status done | DELIVER → deliver → delivered → (検収) → settled |
| llm_judge = 品質の印象採点 | 3点照合 + 原文適合（+ 監査抽選の対象） |
| 完了 = 宣言evaluator全PASS | 納品 = 全PASS + 宣言 + 即時反証held。完了 = 検収 |
| verdict台帳が正本 | claims台帳（較正）が正本。verdictは監査の記録 |
| 判定サブエージェントの増設 | 反証手続き（機械・現実）への転嫁。judgeは抜き取り |

温存: World Model / Query / lesson / decision・situation層 / failure→検出器（CAPEX化の器官）/
事前固定（plan hash）/ 経験監査。これらは「生成側に良い文脈を食わせる」「一度負けた種目を
機械に焼き付ける」という、天井と較正に実際に効く側の器官である。

## 限界（正直な開示）

- 現実が安く答えない領域（純粋な戦略助言）では、反証手続きは書けない。そこでの正直な納品は
  壮大な答えではなく、検証可能な形に縮めた主張と `unfalsifiable` の開示である
- 短絡性の根は訓練（エピソード末尾で報酬が確定する構造）にあり、OSは根治できない。
  OSにできるのは、欠損を封じ込めることと、欠損の実測（較正台帳）を生むことまでである
