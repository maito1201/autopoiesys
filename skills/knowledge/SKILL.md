# knowledge — 器へ書き戻す

器の場所は作業中リポジトリの CLAUDE.md にある「知識の器:」の行。無ければ本人に聞く。規約は器の README.md が正で、ここには繰り返さない。

## 手順

1. このタスクで世界（コード・データ・本人）から新しく分かったことを列挙する。要約で済ませた文書由来の知識は含めない
2. 本人に訂正された箇所を列挙する。訂正は最も価値の高い1行。訂正前の自分の理解を「撤回」として脚注に残す
3. それぞれを INDEX.md で該当トピックへ割り当てる。該当が無ければ既存トピックを広げるか、INDEX が40行未満なら新トピックを作る。40行以上なら何かを削ってから
4. 既存の行と同じ事実なら1行に統合し、確認日と信用ラベルを更新する。矛盾したら確認済みを優先し、脚注に差異を残す
5. 「いつ」がある教訓（〜する前に・〜した後に）は topics ではなく moments/ の該当ファイルへ。該当が無く同種の失敗が2回目なら新しい moment を作る。1回目は topics に置く
6. 成果物を出したなら hypotheses.md に1行: この判断が外れていたら、何がいつ観測されるか
7. `scripts/check.sh <器のパス>` を実行し、NG があれば削る

## 禁止

- 統治語彙（台帳・verdict・較正・evaluator・宣言・タスク番号）を書くこと
- 出典を本文に書くこと。脚注へ
- 文書から要約しただけの行に「確認済み」を付けること
- 書くために読み直す時間を、タスクの前に前払いすること。書くのは分かった直後だけ
